# Provider Descriptor Migration Ledger

Inventory taken at `origin/release` @ `2cefa3ae4115f817f75a415b6bc70fc3ecaed2d3`. TypeSafe was added afterwards (#1761) and is included below; the 25-entry count matched `origin/release` @ `f536fd091`.

`mistral`, `huggingface`, `deepseek`, `laya` and `xor` have since migrated to the JSON catalog and been removed from `HAND_DESCRIPTORS` (#1781; `laya` in the PR that added `src/lib/providers/catalog/laya.json`; `xor` in the PR that added `src/lib/providers/catalog/xor.json`) — see [Migrated](#migrated-5) below — and `perplexity-decider` and `cloudflare-clef` (decision-only, like TypeSafe) were added as hand descriptors afterwards. Net effect: the 25-entry baseline minus the 3 baseline entries that migrated (`mistral`, `huggingface`, `deepseek`), plus the 2 added afterwards that stay hand-written (`perplexity-decider`, `cloudflare-clef`), leaves **24 entries currently in `HAND_DESCRIPTORS`** (`src/lib/factories/providerDescriptors.ts`). `laya` and `xor` are not part of the 25: they were added to `HAND_DESCRIPTORS` after the baseline and then migrated, so they cancel out and neither is subtracted from it. The category counts below (Shared adapter needed / Must remain class / Must remain core class) cover exactly those 24; the 5 migrated providers are recorded separately as done and no longer count toward "what remains."

This ledger records, per provider, why it is (or isn't) a JSON-catalog migration candidate, so "add a provider" work doesn't re-litigate the same analysis per PR.

Every verdict allows one thing regardless of class: the **static descriptor metadata** (name, aliases, default model, credential env var names, setup URL) can always move into a class-backed JSON record. "Must remain class" means the _execution_ — the inference loop (`generate`/`stream`/`decide`, per the provider's `inferenceKinds`), auth, media pipelines — cannot be reduced to declarative catalog data; it does not mean the provider is exempt from descriptor consolidation.

## Shared adapter needed (9)

Three adapter families, not nine one-off migrations:

**Local-runtime adapter** (`ollama`, `lm-studio`, `llamacpp`) — one OpenAI-compatible local-runtime adapter with optional auth, model discovery/probe, actionable transport errors, timeout policy, optional embeddings. Vendor-specific pull/diagnostic guidance becomes adapter data.

**Embedding-only adapter** (`voyage`, `jina`, `cohere`) — one embedding-only provider adapter parameterized by path, request shape, batch size, response-extraction/index policy, unsupported-surface messages. `jina` extends it with an optional rerank operation profile (don't force reranking into the boolean capability shape). `cohere` composes this with a generic OpenAI chat adapter (it has both `/compatibility/v1` chat and native `/v2/embed`); preserve its batch limit and body-field quirks in the embedding profile.

**Image-generation adapter** (`stability`, `ideogram`, `recraft`) — one image-generation adapter family: explicit multipart vs JSON request profile, base64-vs-URL response profile, custom auth-header support, model-path mapping as data. SSRF and bounded-read policy remain shared mandatory behavior, not per-vendor opt-outs.

Same `noul` / `choice` / `score` vocabulary, but with Cloudflare's own response envelope, limits and a separate `images` array; distinct from the catalog's `cloudflare` text provider though it shares its `CLOUDFLARE_API_KEY` and `CLOUDFLARE_ACCOUNT_ID` — so no OpenAI-compatible chat shape to hang a catalog entry on.                 |

## Must remain core class (1)

| Provider            | Why                                                                                                                                                                                                                                                                           |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `openai-compatible` | This is the generic protocol surface itself, not a direct vendor. It should consume shared descriptor/config primitives but must never become a fixed-vendor JSON row — collapsing it into the catalog would conflate "the adapter" with "an entry in the adapter's catalog." |

## Suggested execution order

The former steps 1–2 below (`mistral`; `huggingface`, `deepseek`) are complete, and `laya` and `xor` have moved too — see [Migrated](#migrated-5) above. What remains:

1. **Three shared adapters** (local-runtime, embedding-only, image-generation) — each unlocks 3 providers at once; build once, migrate three.
2. **`google-ai`** descriptor-only JSON metadata — proof of concept for moving static descriptor data out of a "must remain class" provider without touching its execution.
3. Direct-vendor "must remain class" providers (`bedrock`, `openai`, `vertex`, `anthropic`, `azure`, `sagemaker`, `nvidia-nim`) get descriptor-only JSON metadata migrations, execution untouched — lower priority, cosmetic consolidation only.
4. Aggregators (`litellm`, `openrouter`), the core adapter (`openai-compatible`), and the decision-only providers (`typesafe`, `perplexity-decider`, `cloudflare-clef`) are excluded from the first-class-count migration priority entirely — the first three add no direct-vendor coverage however they're implemented, and `typesafe`/`perplexity-decider`/`cloudflare-clef` are `decide`-only providers with no `generate`/`stream` surface to migrate at all.
